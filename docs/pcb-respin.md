## 1. 今回の失敗と、その本質

**ADCのデータ3本がFPGAに届いていません。** `adc_d[2]`(FPGAピン42)、
`adc_d[3]`(41)、`adc_d[6]`(31)。8ビットのうち実質24階調(256階調中)しか
使えておらず、映像の上位3バーが同じ値に潰れ、色も行ごとに揺れます。

**原因は部品でも実装でもありません。** 以下はすべて測定で除外済みです。

| 疑い | 検証方法 | 結果 |
|---|---|---|
| 半田の開放 | 配置固定のプルテスト(`scripts/scope_pull_variant.py`) | どのビットもプルに追随せず＝開放ではない |
| GNDへの短絡 | テスターで対地抵抗 | 130 kΩ、正常ビット(D5)と同値 |
| AD9280の故障 | **新品の基板＋新品のICで再現** | 同じ3ビットが死ぬ |
| 読み出し経路 | 既知の鋸波を緩衝域に書いて読み返す | 241/256値、全列が誤差1以内で線形 |
| 信号源 | スタビライザー挿入で信号を変更 | 帯状化は不変 |
| 標本化位相 | 5位相すべて | すべて同じ |
| ADCクロックのデューティ | 40% / 60% | 60%はむしろ悪化 |
| IO規格 | LVCMOS33 / 18 / 25 / 12 | すべて同一 |

**残るのはピンの選択です。** そして本質はこうです。

> **ピンが使えるかどうかを、資料を読んで判断した。実測しなかった。**

CLAUDE.md には当時から次の警告が書かれていました。

> ピン27–31 / 41 / 42 の実際のバンクVCCIOをSipeedの回路図で確認してから
> `LVCMOS33` を信用すること。入力バスのバンク電圧が違うと、**無言でデータが化ける**。

この警告を実行しなかったことが、基板一枚分の損失になりました。

## 2. 次の版で必ず守ること

### 2.1 ピンは発注前に実測する（最重要）

推測も資料も信用しません。**手元のTang Nanoで実際に試験します。**

```sh
# 候補ピンを pin_probe[7:0] に割り当てた .cst を作り、
# プルアップ版とプルダウン版をそれぞれ書き込んで画面のセルを読む
make ntsc            # PROBE_ON=1 でビルドしたものを使う
```

判定は単純です。

- **プルアップで1、プルダウンで0を返すピン → 自由。使える**
- **どちらかに追随しないピン → 何かが繋がっている。使わない**

死んだ3本は、まさに後者の挙動でした。理由が分からなくても、**この試験だけで
除外できます**。

さらに強い確認として、駆動して読み返す試験(`PIN_TEST=1`)もあります。
**必ず陽性対照(`PIN_TEST=2`、期待値を反転)と対で実行してください。**
比較が走っていなければ、どちらも「異常なし」に見えます。

## 3. アナログ側（v0.1基板の実測にもとづく）

### 3.1 C13 は 100 pF のまま

以前ここには「820 pF〜1 nFに上げてアンチエイリアスとして機能させる」と書いていましたが、
実測で否定されました。折り返しの雑音に見えていたものは、Apiculaがビット0・1・4・5
（ピン27〜30、HDMIと同じバンク）をLVDS受信として組んでいたことが原因で、
`scripts/gowin_pack_io.py` で解決しています。

680 pFに替えた実機では、3.58 MHzの色信号が約2.5 dB落ちるだけでした（100 pFなら0.1 dB）。
LCフィルタも不要です。

### 3.2 AINの直流動作点を部品で決める（次の改版で推奨）

現状、C2より後ろ（AIN側）には直流電位を決める部品がなく、アナログクランプも使っていません。
それでも信号が変換範囲に収まっているのは、おそらくADC入力のサンプリング容量が中点への
抵抗のように働いているためです（仕組みは未確認）。入力機器やADCクロックしだいで動作点が
変わり得るので、部品で決めておきます。

- R2 を 22 kΩ → **10 kΩ** に変更し、CLAMPIN を 1.0 V（VREFの半分）にする
- AIN（TP1）と CLAMPIN（TP3）の間に **47 kΩ** を追加する

計算では、黒一色から白一色まで、どんな絵でも信号は 0.1〜1.75 V に収まります（変換範囲は
0〜2 V）。時定数は47 msで、フィールド単位のゆっくりした変動はデジタル側の黒レベル補正
（フロントポーチの測定）が吸収します。

この変更後は、アナログクランプを有効にしてはいけません。同期先端が1.0 Vに固定され、白が
2 Vで頭打ちになります。ファームは既定で無効です。変更したら、黒い画面と白い画面の両方で、
診断表示の波形の同期先端と白がコード10〜240に入っていることを確かめてください。

**v0.2での対応**：R2 を 10 kΩ にし、47 kΩ の **R19**（0603）を追加しました。R19 は R2 の右隣に
あり、AIN は TP1 へ行く裏面の配線からビア (156.85, 45.45) で取っています。47 kΩ を通る直流の
バイアスなので、AINピンから離れていても支障はありません。

この変更で CLAMPIN が 0.625 V から 1.0 V になるので、クランプを強制オンにする診断ビルド
（`make clampon-program`、`CLAMP_FORCE`）の読みも変わります。v0.1 ではコード80付近、v0.2 では
128付近が正しい値です。

### 3.3 アナログクランプは使わない

C2 が 1 µF だと、クランプの1パルスごとの過渡がライン長を超えて残ります（クランプonで
良品ライン約72%、ロックが発振）。直流再生はデジタルで十分機能しているので、クランプを
使う構成にする必要はありません。C2 は 1 µF のままで構いません。

## 4. 回路図とレイアウトの修正点（v0.1基板、2026-10-03のDRCより）

`hardware/` の基板に `kicad-cli pcb drc --schematic-parity` をかけた結果です。未配線は0、
回路図との不一致も0で、以下は製造は通ったものの、次の改版で直したい点です。

### 4.1 AD9280のグラウンドをGNDベタにしっかりつなぐ（優先）

U1（AD9280）の1番（AVSS）、14番（DRVSS）、16番（THREE-STATE、GNDに固定）は、F.CuのGND
ベタとはサーマルのスポーク1本でしかつながっていません（DRCの「サーマル接続不完全」）。
同じ指摘が C3（10 µF）の2番、R17の2番、J2の2番にもあります。

ただし、ベタだけが頼りなわけではありません。銅箔を調べると、これらの端子には幅0.4〜1 mmの
GND配線が別に引いてあります（1番 → C4のGND、14番 → 左へ1 mm幅、16〜18番 → C12のGND）。
弱いのは、その配線が裏面のベタへ落ちるまでの距離でした。

**v0.2での対応**：それぞれのGND配線の上、端子のすぐ横に GND ビア（0.6/0.3 mm）を1個ずつ
追加しました（(150.8, 33.5)、(140.0, 34.06)、(142.0, 44.05)）。C3の2番は、C13の跡に入れた
GNDビア（4.3）が受け持ちます。

**残っていること**：DRCの「サーマル接続不完全」6件は、ビアを足しても消えません。F.Cu の
GNDゾーンのプロパティで、パッド接続を「PTHのみサーマルリリーフ」にして再塗りつぶしすると、
表面実装の5件が消えます。J2の2番はスルーホールで裏面のベタにつながっているので、残っても
実害はありません。

### 4.2 GND配線が基板端に近すぎる

F.Cu の GND 配線3本（長さ 2.4 mm、2.4 mm、29.6 mm）が、基板端から0.22 mmしか離れていません
（設定は0.5 mm）。内側へ寄せてください。

**v0.2での対応**：幅を1 mmから0.5 mmにして y = 27.0 mm へ移しました。基板端から0.69 mm、
Tang Nanoのパッドから0.25 mmです（端とパッドの間は0.9 mmほどしかないので、1 mm幅のままでは
入りません）。

### 4.3 C13 が Tang Nano のフットプリントの下にある

C13（100 pF、リード部品の円板コンデンサ）がU2（Tang Nano 20K）のコートヤード内にあります。
今の基板ではソケットの高さで逃げていますが、0603のチップ部品にしてAINピンの近くに置けば、
干渉もなくなり、配線も短くなります。値は100 pFのままです（3.1）。

**v0.2での対応**：0603（`C_0603_1608Metric_Pad1.08x0.95mm_HandSolder`、他のコンデンサと同じ）に
替えました。位置は元と同じ、R3とR2の間です。U1の27番のすぐ下は基準電圧のコンデンサ（C6ほか）で
埋まっていて、これ以上は寄せられませんでした。既存のAINとGNDの配線は、そのまま新しいパッドに
届いています。

元のリード部品の穴は、表と裏の配線をつなぐ役も兼ねていました（AINはTP1へ行く裏面の配線、GNDは
C1・C3から来る表の配線と裏のGND）。これはビア2個で置き換えています：AIN (153.35, 46.2)、
GND (153.678, 42.0)。

### 4.4 回路図シンボルの誤記

U2のピン13（FPGA 30番、D5）の名前が「30_IOB14A」になっています。正しくは「30_IOB14B」です
（29番と30番でペア）。電気的には問題ありません。

### 4.5 フットプリントライブラリを同梱する

J3（`RJ-2410N`）と U2（`0my_project`）のフットプリントライブラリがプロジェクトに含まれて
いません。フットプリント自体はPCBファイルに埋め込まれているので開いて編集はできますが、
ライブラリから更新しようとすると失敗します。他の人が編集できるよう、`hardware/` に
ライブラリとプロジェクト用の `fp-lib-table` を入れてください。

コートヤードの重なり（37件）とシルクの重なりは見た目だけの指摘なので、残っていて構いません。

4.4 と 4.5 は v0.2 でも未対応です。`0my_project` は nosuz/kicad-symbols-footprints（GitHub）、
`RJ-2410N` は SamacSys の配布物で、どちらも第三者のものです。公開リポジトリに同梱してよいかを
先に確かめる必要があります。4.4 の誤記は、その上流のライブラリ自体にあります。

**フェライトビーズについて。** v0.1 のリード付きビーズは、下を横切る配線をまたぐジャンパの役も
兼ねていました（FB1 は表のGND配線と裏のGND・AIN配線、FB2 は表のGND配線と裏のCLAMPIN・CLK配線）。
チップ部品ではそれができないので、次のようにしています。

- **FB1** は (160.65, 43.99) に置き、TP7 から U2 の20番へ行く表のGND配線をパッドの間に通して
  います。その配線は、通る部分と斜めの部分だけ幅を 1 mm から 0.6 mm にしました（パッドとの間隔を
  取るため）。+3V3 は元の下側の穴の位置のビアで表へ上げ、+3V3a は元の上側の穴の位置のビアで
  表と裏をつないでいます。取り付け穴 H2 のネジ頭の範囲（半径2.95 mm）には入っていません。
- **FB2** は (159.56, 34.34) に置き、表のGND配線の南側に収めました。Tang Nano の3V3（25番）から
  来る裏の配線は、GND配線の下をくぐってからビア (158.4, 33.4) で表へ上げています。

AD9280 の消費は30 mA台で、このビーズは500 mA・0.3 Ωなので余裕があります。

**シルクについて。** v0.1 と v0.2 は CLAMPIN の電圧が違うので、基板を見て区別できるよう版数を
入れました。テストポイントの対応表は Tang Nano の下にあるので、モジュールを抜いたときにだけ
見えます。裏面に入れるのが理想ですが、Konnect では裏面用の鏡文字が作れませんでした。裏面に
移したいときは、KiCad で文字を選んで裏返してください。部品番号の文字がパッドや他の線に
重なっている箇所（DRCのシルク警告）は、そのままです。

確認結果（`kicad-cli pcb drc --schematic-parity`）：未配線 0、回路図との不一致 0、クリアランス
違反 0、基板端クリアランス違反 0（3件から）、コートヤード内のスルーホール 0（2件から）。残るのは
コートヤードの重なり38件（R19の分が1件増）、サーマル接続不完全6件（4.1）、シルクの警告です。
ERC は14件から6件になり、残りはすべて電源フラグ（PWR_FLAG）が無いことによるものです。

### 4.7 製造ファイル（v0.2、2026-10-03）

`hardware/jlcpcb/production_files/` の BOM・部品配置・ガーバーは v0.2 のものに作り直して
あります（v0.1 のものはタグ `v0.1` にあります）。

**JLCPCBに実装してもらう13種類の部品は、Basic 12種類と Preferred 1種類で、Extended は
ありません。** Preferred は Basic と同じく、Extended の手数料がかからない区分です。v0.1 では
C7 と D1 の2種類が Extended でした。

- **C7** は、タンタルと同じ 3216 サイズのセラミックに替えました。パッドはタンタル用のままで
  載ります。VREF には別に 0.1 µF（C6）が付いているので、セラミックで問題ありません。シルクの
  極性マークは残っていますが、無極性なので向きは問いません。
- **D1** は、SOD-323 に手数料なしの双方向品がなかったので、小さいパッケージに替えました。
  双方向・5 V という性質は同じで、容量は 15 pF です（映像の帯域には影響しません）。片方向の
  保護ダイオードは使えません。信号が 0 V より下に振れる入力機器で、同期の先端を削るからです。
- 手はんだで付けるのは、U1（AD9280）、U2 のソケット、コネクタ、テストポイントです。AD9280 は
  JLCPCB では Extended（在庫も少ない）なので、BOM には入れていません。

**作り方。** ガーバーとドリルは `kicad-cli` で出しています。

```sh
kicad-cli pcb export gerbers -l F.Cu,B.Cu,F.Paste,B.Paste,F.SilkS,B.SilkS,F.Mask,B.Mask,Edge.Cuts \
    --no-protel-ext --subtract-soldermask -o OUT/ hardware/tangADC.kicad_pcb
kicad-cli pcb export drill --format excellon --drill-origin absolute --excellon-units in \
    --excellon-zeros-format decimal --excellon-separate-th --generate-map --map-format pdf \
    -o OUT/ hardware/tangADC.kicad_pcb
```

ファイル名は、これまで使っていた JLCPCB 用プラグインの名前（`CuTop`、`MaskTop` など）に
合わせています。この方法で v0.1 の基板から作り直すと、9層のうち7層とドリル2つが、実際に
発注したファイルと日付以外は完全に一致しました。残りの2層の違いは、裏面の銅のベタの頂点が
1つ違うことと、表のレジストに取り付け穴4か所の開口があるかどうかで、どちらも仕上がりには
影響しません。

BOM と部品配置（CPL）もプラグインと同じ書式です。回転角は、変更していない部品については
v0.1 の値をそのまま引き継いでいます。プラグインの記録（`hardware/jlcpcb/project.db`）も
同じ部品番号に更新してあるので、今後プラグインで作り直しても同じ結果になります。

発注画面では、部品の向きのプレビューを必ず確認してください。特に D1 は新しいパッケージです。
